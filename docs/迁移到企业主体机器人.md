# 迁移到「企业主体」新机器人 —— 准备清单

> 场景：个人主体有灰度限制，所以用朋友的企业主体（`<主体名>`）批了一个新机器人应用，
> 你的 QQ 已加为**超管**，并附赠一个**登录密钥**。目标：把「蓝色大肥鱼」复刻到新机器人上。
>
> 本文是**动手前的准备清单**。结论先给：**迁移本身几乎不用改代码**（机器人身份全在 `.env` 里），
> 但有一个**决定性陷阱** —— 见下面第一节。

---

## 🔴 一、决定性事实：openid 是**按机器人应用隔离**的

官方文档（[API 调用指南 · 唯一身份机制](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/api-call-guide.html)）原话：

> 不同的 `bot(AppID)` 获取到的用户 `openid`、群 `openid`、频道 `openid` **均不相同**，
> 若跨业务有关联用户身份需求，**后续**提供跨 `AppID` 绑定后，使用类似 `unionid` 的机制打通身份。

**⇒ 换机器人应用 = 下面这些全部作废、必须重新采集：**

| 项 | 旧值能用吗 | 说明 |
|---|---|---|
| **主人 openid** | ❌ **必须重采** | 你现在那个 `156D38…` 是**旧机器人**给你的。新机器人看你是**另一个 32 位 ID** |
| **所有群 openid** | ❌ 全部变 | 同一个群，新机器人看到的是**另一个 ID** |
| 群友 openid | ❌ 全部变 | 记忆/限流/冷却都按这个 key，迁移后自动全清空（无害） |
| **群级设置** | ❌ 要重开 | 「**获取群内全部消息**」是 **(群, 机器人)** 维度的开关，**必须由群主在新机器人上重新授权** |

**⚠️ 填错主人 openid 的后果**：`isOwner()` 永远 false，「只服从主人」的规则**静默失效** ——
没有任何报错，你就是查不出为什么。（这是本项目踩过的坑，见项目文档「主人标识」一节。）

**✅ 一个好消息**：因为 openid 按应用隔离，所以**旧的 `.env` 配置永远有效** ——
回滚只要换回来 + 重启，旧机器人立刻恢复正常，不会两头不靠。

## 二、需要准备的东西

### A. 从新机器人后台拿到（你去找朋友/超管后台确认）

| # | 要拿什么 | 在哪 | 备注 |
|---|---|---|---|
| 1 | **新 AppID** | 开放平台 → 开发设置 | 也常写作 `bot(AppID)` |
| 2 | **AppSecret（机器人密钥）** | 开放平台 → 开发设置 | ⚠️ 你说的「**登录密钥**」请确认一下是**这个**，还是另一种密钥（见下面"三件要你确认的事"） |
| 3 | 是否**沙箱/未发布** | 开放平台首页会标 | 沙箱只能拉进后台配置的「测试群」 |
| 4 | 有没有 **IP 白名单** | 开放平台 → 开发设置 | 若有 → 必须加服务器公网 IP，否则鉴权会失败 |
| 5 | **灰度能力清单** | 开放平台各功能页的开关 | 见第五节（这是唯一"要改代码才能用上"的部分） |

### B. 环境上要做的（不用改代码）

| # | 做什么 | 为什么 |
|---|---|---|
| 6 | 把新机器人拉进**一个测试群** | 得先能收到消息，才知道自己的新 openid（鸡生蛋，见步骤） |
| 7 | 让**群主**在手机 QQ 里开「机器人可获取的群聊消息范围 → **获取群内全部消息**」 | 不开的话只能收到 **@ 消息** → 链接解析 / 识图 / 关键词这些**"无需 @"的功能全部失效**。⚠️ 这个只有**群主**能改 |
| 8 | 备份服务器现状 | `cp .env .env.bak-$(date +%F)` + `tar czf data-$(date +%F).tgz data/` |

### C. **不用换**的（跟 AI 侧有关，不是机器人侧）

| 项 | 说明 |
|---|---|
| `AI_API_KEY` / 模型 / `BUDGET_*` | 还是**同一个 DeepSeek 账号**，不用换 |
| `OG_PROXY_BASE` | GitHub 预览图中转，走你自己的域名，不变 |
| 服务器 / 域名 / 日志网页密码 | 不变 |
| 代码 | **一行都不用改** —— appId/secret/owner 全在 `.env` |

## 三、三件要你确认的事

1. **「登录密钥」到底是哪个？** 开放平台里跟机器人有关的密钥主要是 **AppSecret**。
   如果那个"登录密钥"是别的东西（比如管理端登录凭据），**别往 `.env` 里塞** ——
   我们的代码只需要 AppID + AppSecret。
2. **旧机器人还继续跑吗？** ⚠️ 两个机器人**都在同一个群里会双重回复**
   （两条一模一样的卡片/回话）。而且 🔴 **AI 预算是共享的**（同一个 key、同一个钱包），
   两个实例各记各的账 = 上限**实际翻倍**。
   ⇒ 建议：**二选一**。过渡期就让新机器人只在测试群跑，确认没问题再把旧的移出群。
3. **灰度具体开了哪些能力？** 见第五节。

## 四、迁移步骤（最小路径，预计 20 分钟）

```bash
# ① 备份
cd /opt/xiaolanjing && cp .env .env.bak-$(date +%F-%H%M) && tar czf /root/data-$(date +%F).tgz data/

# ② 改 .env：换 AppID / AppSecret，**主人 openid 先清空**（还不知道新的）
#    用 printf | tee，别用 nano 粘贴（CRLF 会污染，见项目文档的坑）
grep -n 'QQ_BOT_APPID\|QQ_BOT_SECRET\|BOT_OWNER_OPENID' .env

# ③ 重启，看鉴权
systemctl restart xiaolanjing && sleep 6
journalctl -u xiaolanjing -n 30 --no-pager | grep -E '鉴权|启动|开关状态|❌'
#    ✅ 期望看到「鉴权成功」。❌ 若失败：先查 AppSecret 和 IP 白名单

# ④ 在测试群里 @ 一下新机器人（随便说句话）
#    ⚠️ 此时它会回话但**不认主人** —— 因为 BOT_OWNER_OPENID 还是空的
#       这是**刻意安全**的：没配主人时，开关机命令谁都不能用（启动日志会警告）

# ⑤ 挖出你的新 openid
node -e "
const fs=require('fs');
const seen=new Map();
for(const f of fs.readdirSync('/opt/xiaolanjing/data').filter(x=>x.startsWith('events-'))){
  for(const line of fs.readFileSync('/opt/xiaolanjing/data/'+f,'utf8').split('\n')){
    if(!line.trim())continue;
    try{const a=JSON.parse(line).d?.author; if(a&&a.member_openid) seen.set(a.member_openid,a.username);}catch(e){}
  }
}
console.log('--- 出现过的人（新机器人的视角）---');
for(const [id,name] of seen) console.log(String(name).padEnd(14), id);
"
#    找到你自己那行 → 复制那 32 位 ID

# ⑥ 填回去并重启
#    BOT_OWNER_OPENID=<你刚才挖到的>
systemctl restart xiaolanjing
```

**⑦ 功能自检清单**（每项都验一遍）：

| 项 | 怎么验 | 期望 |
|---|---|---|
| 鉴权 | 启动日志 | 「鉴权成功」 |
| **主人识别** | 私聊发一句 | 有回应（说明 openid 填对了） |
| **开关机** | @它说「关机」→ 再说「开机」 | 只有你能操作；别人说无效 |
| 链接解析 | 群里贴一个 GitHub 链接 | 出卡片（含预览图） |
| 识图 | 群里发一张图 / 一个动图 | 有描述；**动图要能看出动作** |
| 全量消息 | 不 @ 它、只说个关键词 | 50% 概率引用回复（能，说明群级开关开了） |
| 日志网页 | 手机开 `http://<IP>:8080/?p=<密码>` | 开关状态/额度正常 |
| 戳一戳 | —— | **仍然不行**（官方不推这个事件，换企业主体也一样） |

## 五、灰度能力：唯一"要改代码才能用上"的部分

个人主体受限、企业主体放开的，**可能**包含（以你后台实际能开的为准）：

| 能力 | 对项目的意义 | 要不要改代码 |
|---|---|---|
| **主动消息推送** | ⭐ 我们一直挂着的待办「**欢迎新成员 / 定时主动说话**」就能做了 | ✅ 要加代码 |
| 更高的调用/推送额度 | 现在 `dailyCallLimit: 800`、识图 300/天，可能要往上调 | 改配置即可 |
| 更多消息类型 / 按钮组件 | 卡片可以带按钮（比如"戳我"） | ✅ 要加代码 |
| 频道（Guilds）相关 | 本机器人只做群聊，用不上 | 不用 |

> 📌 **建议顺序**：先**原样复刻**（不改代码，验证新机器人能跑通），
> **再**单独评估灰度能力要不要接。别两件事一起做 —— 出问题时分不清是迁移没弄好还是新功能有 bug。

---

## 六、回滚

```bash
cd /opt/xiaolanjing
cp .env.bak-<时间戳> .env       # 换回旧 AppID/AppSecret/主人 openid
systemctl restart xiaolanjing
```

因为 openid **按应用隔离**，旧的配置**一直有效**，回滚是安全且即时的。
